새 기능 작업을 시작한다. 이번 작업 이름은 다음과 같다.

$ARGUMENTS

작업 이름이 비어 있으면 무엇을 할 작업인지 먼저 사용자에게 묻고, 답을 받기 전에는 브랜치를 만들지 마라.

## 순서

1. `git status --short --branch`로 작업 폴더가 깨끗한지 확인한다. 커밋되지 않은 변경이 있으면 **브랜치를 만들지 말고 멈춘 뒤** 무엇이 남아 있는지 보고하고 어떻게 할지 묻는다. 사용자 변경을 임의로 되돌리거나 stash하지 마라.

2. `develop`을 원격과 맞춘다.

   ```
   git switch develop
   git pull --ff-only origin develop
   ```

3. 작업 이름에서 영문 소문자와 하이픈으로 된 짧은 슬러그를 만들어 브랜치를 생성한다. 시작점을 반드시 명시한다. 원격에 같은 이름이 있으면 다른 슬러그를 쓴다.

   ```
   git switch -c feature/<슬러그> origin/develop
   ```

4. `docs/TASKS.md`를 연다. 이번 작업에 해당하는 항목이 있으면 `[-]`로 바꾸고 뒤에 브랜치 이름을 적는다. 해당 항목이 없으면 "진행 중" 절에 새로 추가한다.

5. 코드를 쓰기 전에 관련 기존 구현·테스트·공통 컴포넌트를 먼저 찾아 읽고, 무엇을 어떻게 바꿀지 계획을 한 번 보여 준다. 같은 역할의 코드가 이미 있는지 `rg`로 검색한 뒤에 새 타입이나 유틸을 만든다.

## 금지

- `feature/yj-work`와 `origin/feature/growing-space-design-refresh`는 팀원 브랜치다. 체크아웃·수정·병합·삭제하지 마라.
- 작은 UI 작업을 DB나 API 변경으로 확대하지 마라. 화면에 필요한 데이터가 이미 있으면 프론트 구조와 CSS만 고친다.
- 요청 범위를 넘는 리팩터링과 인접 코드 정리를 하지 마라.
