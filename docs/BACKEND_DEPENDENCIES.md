# Laravel·데이터베이스 의존 기능 정리

이 문서는 프론트엔드 프로토타입에서 확인할 수 있는 범위와 Laravel API·데이터베이스가 준비되어야 완성할 수 있는 범위를 구분한다.

## 지금도 완성 가능한 범위

- 작물 기준 데이터의 타입, 정적 카탈로그와 출처 관리
- 격자 생성, 배치 좌표와 면적 계산
- 포기 수 계산
- 간격·시기·연작 규칙의 순수 계산과 경고
- 일정 생성 규칙과 화면 흐름
- 접근성, 반응형 화면과 입력 검증

이 범위는 입력과 출력이 명확한 도메인 규칙부터 구현하고 단위 테스트할 수 있다. 이후 Laravel API가 추가되어도 계산 규칙은 그대로 재사용한다.

## 프론트엔드 프로토타입은 가능하지만 서버 없이는 미완성인 범위

### 사용자 데이터 저장

- 공간·시즌·배치·일정·작업·성장·수확 기록의 영구 저장
- 사용자별 데이터 분리와 소유권 검사
- 여러 기기에서 같은 데이터 조회
- 브라우저 저장 데이터의 백업·복구와 서버 이전
- 동시에 수정할 때 충돌 방지와 트랜잭션 처리

현재 브라우저 저장소는 한 브라우저 안에서 화면 흐름을 검증하는 용도다. 로그아웃·계정 변경과 무관하게 데이터가 남으므로 실제 사용자 저장소로 취급할 수 없다.

### 일정과 알림

- 서버 기준 일정 저장과 완료 이력
- 정해진 시간에 실행되는 스케줄러
- 이메일·푸시 알림 발송과 재시도
- 읽음 상태와 알림 설정 동기화

화면과 일정 계산은 먼저 만들 수 있지만, 사용자가 앱을 닫은 뒤에도 알림을 보내려면 Laravel 스케줄러·큐와 데이터베이스가 필요하다. 현재 프론트엔드 대시보드는 브라우저에 저장된 미완료 일정 중 기한이 지났거나 7일 안에 예정된 항목을 앱 내부 알림으로 보여준다. 이 알림은 앱을 열어야만 확인할 수 있으며 발송·읽음 상태를 제공하지 않는다.

### 시즌 기록

- 작업·물주기·성장·수확 기록 누적
- 이미지 업로드와 파일 저장소 연결
- 기록 수정 이력과 시즌 마감 스냅샷

## Laravel·데이터베이스가 있어야 시작 의미가 있는 범위

### 실제 인증

- 회원가입, 이메일 중복 검사와 로그인
- 비밀번호 해시 저장, 재설정과 이메일 인증
- 세션 또는 API 토큰 발급·폐기
- 계정 상태, 탈퇴와 개인정보 처리
- 보호 API의 인증·인가

### 관리자 기준 데이터 관리

- 작물·과·분류·재배 규칙 CRUD
- 운영자 권한과 변경 이력
- 출처 검토일, 공개 상태와 데이터 버전 관리
- 잘못된 기준 데이터 신고 처리

현재 작물 기준 데이터는 코드에서 버전 관리하며, 향후 Laravel 시드 데이터와 관리자 API의 원형으로 사용한다.

### 결제와 공동 관리

- 요금제·구독·결제·환불 상태 검증
- 웹훅 서명 검증과 중복 결제 방지
- 공동 텃밭 초대, 역할과 권한 검사
- 공동 수정 내역과 활동 로그

결제와 권한은 화면만으로 안전성을 검증할 수 없으므로 프론트엔드 모의 기능을 완성 기능처럼 제공하지 않는다.

## 구현 순서에 미치는 영향

1. 작물 기준 데이터와 순수 계산 규칙을 먼저 완성한다.
2. 격자 배치·수량·검사 화면은 브라우저 임시 저장으로 사용자 흐름을 검증한다.
3. 일정·기록은 데이터 구조와 UI까지만 준비하고 영구 저장 기능은 Laravel 이후 연결한다.
4. 실제 인증, 관리자, 알림 발송, 결제와 공동 관리는 Laravel 단계에서 구현한다.
