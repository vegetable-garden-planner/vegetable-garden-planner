# Laravel·데이터베이스 의존 기능 정리

이 문서는 프론트엔드 프로토타입에서 확인할 수 있는 범위와 Laravel API·데이터베이스가 준비되어야 완성할 수 있는 범위를 구분한다.

2026-08-11 기준으로 세션 인증, 작물 조회, 재배 공간, 재배 시즌, 텃밭 배치, 재배 일정, 시즌 기록과 물주기 일정·완료·미루기 API가 구현되었다. 이 범위의 영구 데이터는 Laravel 데이터베이스가 단일 기준이며, 예전 물주기 `localStorage` 프로토타입은 제거했다.

## 지금도 완성 가능한 범위

- 작물 기준 데이터의 타입, 정적 카탈로그와 출처 관리
- 격자 생성, 배치 좌표와 면적 계산
- 포기 수 계산
- 간격·시기·연작 규칙의 순수 계산과 경고
- 일정 생성 규칙과 화면 흐름
- 접근성, 반응형 화면과 입력 검증

이 범위는 입력과 출력이 명확한 도메인 규칙부터 구현하고 단위 테스트할 수 있다. 이후 Laravel API가 추가되어도 계산 규칙은 그대로 재사용한다.

## 서버 저장은 구현되었지만 화면 연결 또는 후속 인프라가 필요한 범위

### 사용자 데이터 저장과 화면 연결

- 공간·시즌·배치·재배 일정·시즌 기록·물주기 일정의 Laravel 영구 저장
- 사용자별 데이터 분리, 소유권 검사와 여러 기기 조회
- `ETag`·`If-Match` 및 트랜잭션을 이용한 동시 수정 충돌 방지
- 물주기 일정 화면과 Laravel API 클라이언트 연결
- 남아 있는 브라우저 임시 저장 기능의 단계적 서버 이전

서버 API가 구현된 도메인에서는 브라우저 저장소를 실제 사용자 저장소로 사용하지 않는다. 아직 서버에 연결되지 않은 임시 기능도 로그아웃·계정 변경과 무관하게 데이터가 남을 수 있으므로 영구 데이터로 취급하지 않는다.

### 일정과 알림

- 서버 기준 물주기 일정 저장, 완료·미루기 이력과 완료 취소
- 정해진 시간에 실행되는 스케줄러
- 이메일·푸시 알림 발송과 재시도
- 읽음 상태와 알림 설정 동기화

물주기 일정의 데이터베이스 저장과 상태 변경 API는 구현되었다. 사용자가 앱을 닫은 뒤에도 알림을 보내려면 별도로 Laravel 스케줄러·큐와 발송 채널을 연결해야 한다. 현재 대시보드 알림 계산은 앱 내부 표시용이며 발송·읽음 상태를 제공하지 않는다.

### 시즌 기록

- 작업·성장·수확 시즌 기록과 별도 물주기 완료 기록 누적
- 이미지 업로드와 파일 저장소 연결
- 기록 수정 이력과 시즌 마감 스냅샷

## Laravel·데이터베이스가 있어야 시작 의미가 있는 범위

### 실제 인증

- 회원가입, 이메일 중복 검사와 로그인
- 비밀번호 해시 저장, 재설정과 이메일 인증
- 세션 또는 API 토큰 발급·폐기
- 계정 상태, 탈퇴와 개인정보 처리
- 보호 API의 인증·인가

### 관리자 기준 데이터 관리

- 작물·과·분류·재배 규칙 CRUD
- 운영자 권한과 변경 이력
- 출처 검토일, 공개 상태와 데이터 버전 관리
- 잘못된 기준 데이터 신고 처리

현재 작물 기준 데이터는 코드에서 버전 관리하며, 향후 Laravel 시드 데이터와 관리자 API의 원형으로 사용한다.

12번 기능의 API 계약은 먼저 정의하되 실제 완료 조건은 Laravel 이후로 둔다. 관리자 기능은 다음 서버 보장이 모두 있어야 한다.

- `member`와 `admin` 역할을 데이터베이스에 저장하고 모든 관리자 요청에서 서버가 권한 검사
- 작물 slug의 유일성, 월 범위, 포기 간격과 출처 관계를 Laravel 요청 검증과 데이터베이스 제약으로 재검사
- `draft`, `published`, `archived` 공개 상태에 따라 일반 사용자 조회 결과 분리
- 배치·일정에서 참조 중인 작물의 물리 삭제 금지와 보관 처리
- `version`, `ETag`, `If-Match`를 사용한 동시 수정 충돌 방지
- 관리자 ID, 변경 시각과 수정 전·후 값을 남기는 변경 이력

프론트엔드 `localStorage`로 관리자 저장을 흉내 내면 권한·공용 데이터·관계 무결성을 검증할 수 없으므로 구현하지 않는다.

### 결제와 공동 관리

- 요금제·구독·결제·환불 상태 검증
- 웹훅 서명 검증과 중복 결제 방지
- 공동 텃밭 초대, 역할과 권한 검사
- 공동 수정 내역과 활동 로그

결제와 권한은 화면만으로 안전성을 검증할 수 없으므로 프론트엔드 모의 기능을 완성 기능처럼 제공하지 않는다.

## 구현 순서에 미치는 영향

1. 작물 기준 데이터와 순수 계산 규칙을 먼저 완성한다.
2. 격자 배치·수량·검사 화면은 브라우저 임시 저장으로 사용자 흐름을 검증한다.
3. 인증·공간·시즌·배치·재배 일정·시즌 기록·물주기 영구 저장은 Laravel로 구현했다.
4. 물주기 화면을 새 API에 연결하고, 알림 발송·파일 업로드·관리자·결제·공동 관리는 이후 단계에서 구현한다.
